# BGRA Input and Output Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accept `{ data, format: 'bgra' }` images everywhere an image is taken, and return BGRA from the `quantize*` functions for BGRA input. Output for existing inputs is byte-identical.

**Architecture:** The C side gets a `PixelLayout` (stride, R and B offsets, has-alpha) read at run time from the format code (`rgba` 0, `rgb` 1, `bgra` 2). It is used at every pixel read and write, with nothing compiled twice. JS adds the code and the name, plus a shared `channels(format)` helper. The worker entry and the clustering format are unchanged.

**Tech Stack:** C++17 compiled to WASM with Emscripten (`em++`), JS (Babel to ESM and CJS), vitest, TypeScript declaration tests, Vite/webpack browser tests.

**Spec:** `docs/superpowers/specs/2026-11-20-bgra-design.md`

## Global Constraints

- Output for `'rgb'`, `'rgba'`, `ImageData` and bare `Uint8Array` input stays byte-identical: `test/golden.test.js` passes with no `UPDATE_GOLDEN`.
- No new C exports, export signatures, options, functions or error codes. The clustering format and `formatVersion` are unchanged.
- `imageFormats` is `['rgb', 'rgba', 'bgra']` in that order, frozen, from both entries. `ImageFormat` is `'rgb' | 'rgba' | 'bgra'`.
- Bare `Uint8Array` and `ImageData` stay RGBA, and their hints and messages are unchanged.
- No templating of `map_pixels` or `ClusteringJob` on the layout.
- Commits are authored by the user and carry no `Co-Authored-By` or other trailers.
- Tests import `dist/`, so rebuild before running them. `npm run build:wasm` after C++ changes, `npm run build` after JS or types. Emscripten: `source ~/.local/share/emsdk/emsdk_env.sh`.
- Long output goes to files under the scratchpad (`$S` = `/tmp/claude-1000/-home-rohan-Programming-agglomerative-clustering/02789644-56ba-44be-bbec-8361bb15f796/scratchpad`). Read only the tail.

## Review Focus

1. **A `Uint8ClampedArray` subarray as BGRA data** (non-zero `byteOffset`) must read its own bytes, as RGBA does. Test in Task 1.
2. **Empty and fully transparent BGRA images:** a header-only clustering and an empty palette. Mapping visible BGRA pixels to an empty palette throws `invalid-argument` (`checkNotEmpty` reads alpha at index 3), and a fully transparent one doesn't. Test in Task 1.
3. **Dithering BGRA without a width** throws the same `options.width` error as RGBA. Test in Task 2.
4. **A BGRA result fed back in:** `quantizeWithPalette(await quantizeWithPalette(img, p), p)` returns identical bytes and `format: 'bgra'`. Test in Task 1.
5. **The worker with `transfer: true`:** a BGRA image is moved and quantized the same as on the main thread. Test in Task 2.

- [ ] **Step 3: Implement `PixelLayout` and use it at every C++ read and write site**

- `ClusteringJob` keeps a `PixelLayout layout` in place of `image_format`. `limit` becomes `image_length - (stride - 1)`, and `increment` becomes `layout.stride`.
- `binary` and `weight_alpha` test `layout.alpha` in place of `image_format == 0`.
- The histogram key is `pixel[r] << 16 | pixel[1] << 8 | pixel[b]`.
- In `map_pixels`, every `pixel[0], pixel[1], pixel[2]` becomes `pixel[L.r], pixel[1], pixel[L.b]`, and every `image_format == 0 && pixel[3] < skip_below` becomes `L.alpha && …`.
- The `_quantize` sink writes `out[L.r] = colour[0]`, `out[1] = colour[1]`, `out[L.b] = colour[2]` (zeros for no colour) and copies alpha when `L.alpha`.
- `has_transparent_entry` and `_quantize_indices` test `L.alpha` in place of `image_format != 0` / `== 0`. Their `p * 4 + 3` reads are already right for both 4-channel layouts.

- [ ] **Step 4: Implement the JS side**
