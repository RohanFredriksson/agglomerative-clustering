**Goal:** Add `'rgbx'`, `'bgrx'`, `'rgba-premultiplied'` and `'bgra-premultiplied'`, narrow `quantize*` result types, fix three older bugs, and bring messages and docs up to the exploratory round's findings. All on `feat/bgra` (PR #31).

**Architecture:** `PixelLayout` in `src/clustering.cpp` grows `premultiplied` and an `opaque` flag (formats whose fourth byte isn't alpha). Every colour read goes through one helper that un-premultiplies through a table when needed, and the `_quantize` sink writes 255 or premultiplies again. JS gains the names and codes and a `hasAlpha(format)` helper. Types gain `RawImage<F>` and `RawResult<I>`.

**Tech Stack:** C++17 to WASM with Emscripten (`em++`), JS (Babel), vitest, TypeScript declaration tests, Vite/webpack browser tests, Electron (one-off check).

**Spec:** `docs/superpowers/specs/2026-11-20-bgra-design.md` (amended after the exploratory round; approved). Tester notes: `/home/rohan/Programming/ac-explore-bgra/FINDINGS.md`. Their projects are in the same folder, without `node_modules`.

## Global Constraints

- `imageFormats` is exactly `['rgb', 'rgba', 'bgra', 'rgbx', 'bgrx', 'rgba-premultiplied', 'bgra-premultiplied']`, frozen, from both entries.
- C format codes: `rgba` 0, `rgb` 1, `bgra` 2, `rgbx` 3, `bgrx` 4, `rgba-premultiplied` 5, `bgra-premultiplied` 6. No export changes its signature.
- Golden passes with no `UPDATE_GOLDEN`. The only intended output change for previously accepted input is fix 3: indexed output where every pixel is below the `transparent` cutoff.
- Un-premultiply: `c' = a ? min(255, round(c·255/a)) : 0`. Premultiply on output: `round(c·a/255)`, with `round` as half away from zero, i.e. `(c·a + 127) / 255` in integer arithmetic. The tests define both in JS.
- Formats ending in `x` write 255 in the fourth byte of mapped output.
- No new options, functions or error codes. New exported type: `RawResult<I>`. `RawImage` gains a type parameter with a default.
- Commits are authored by the user with no trailers. Build with `source ~/.local/share/emsdk/emsdk_env.sh` first. Long output goes to `$S` (`/tmp/claude-1000/-home-rohan-Programming-agglomerative-clustering/02789644-56ba-44be-bbec-8361bb15f796/scratchpad`), and only the tail is read.
- Big arrays are compared with `Buffer.compare` (vitest's deep equality is slow on megabytes), as `test/bgra.test.js` already does.

## Review Focus

1. **A premultiplied pixel with a channel above its alpha** (invalid data from a buggy producer) clamps to 255, never wraps: `[200, 0, 0, 100]` reads as red 255. Test in Task 1.
2. **Premultiplied output for alpha 0** is exactly `[0, 0, 0, 0]` whatever the palette colour, so it is valid premultiplied data. Test in Task 1.
3. **`'bgrx'` with `transparent: true` or `alpha: 'weight'`:** no transparent entry and no weighting, exactly as `'rgb'`, even when the fourth byte is 0 everywhere. Test in Task 1.
4. **A real `ImageData` from node-canvas**, the `canvas` dev dependency used by `test/setup.js`, still passes validation. The new `colorType` and length checks must not reject it. Test in Task 3.
5. **A user's generic wrapper** `<J extends ImageLike>(img: J) => quantize(img, 4)` still compiles after `ImageResult` changes. A wrapper over `RawImage` (no type argument) gets a result whose `format` is `ImageFormat`. Test in Task 5.
