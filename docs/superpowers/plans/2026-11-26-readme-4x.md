# README for 4.x Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the README as a visual-first page with generated media, current sourced numbers and a use-case gallery.

**Architecture:** One Node script, `docs/media/make.mjs`, generates every image and GIF from the library itself and writes measured figures to `docs/media/results.json`. The README embeds the media by absolute raw URL and cites the results file. A test checks the media budget, and another runs the README's gallery snippets.

**Tech Stack:** Node 24 ESM, `dist/index.mjs`, and these dev dependencies already in `package.json`: sharp, gifenc, fast-png, quantize. Also vitest.

**Spec:** `docs/superpowers/specs/2026-11-26-readme-4x-design.md`

## Global Constraints

- Work in the worktree `/home/rohan/Programming/ac-readme`, on branch `docs/readme-4x`. Never touch `/home/rohan/Programming/agglomerative-clustering`: a spike is running there. `node_modules` is a symlink to that tree's; never run `npm install`/`npm ci`.
- No new dependencies. No change to `src/` or to the library's behaviour.
- **Media budget:** the hero ≤ 1.5 MB; the cards average ≤ 700 KB; the total ≤ 6 MB. At least the hero and three cards are animated.
- **Image URLs** in the README: `https://raw.githubusercontent.com/RohanFredriksson/agglomerative-clustering/master/docs/media/<file>`.
- **Photos:** Kodak (`fixtures/kodak.js`), plus Commons photos only under CC0, PD or CC BY, each credited in `docs/media/CREDITS.md` with its author, licence and URL. No FAL and no CC BY-SA.
- **Palettes:** e-ink is the 7-colour palette from `docs/guides.md` "Fixed palettes". The thread card is "a fixed set of 24 colours (illustrative)", with no brand name.
- **The animation card title:** "Animation: ordered dithering keeps still areas still", over a synthetic pan or zoom. It never says "live video".
- **Every number** in the README and in captions comes from `results.json` or a bench results file, named in an HTML comment beside it. Claims are worded for where the numbers support them.
- **The hero N:** the WebAssembly clustering time plus all 63 cuts (k = 2…64), excluding decoding and resizing, median of 5. `results.json` records the machine, the Node version, the settings and the load average before and after.
- **Commits** are authored as the repo's git user, with no Co-Authored-By or Claude-Session trailers and nothing mentioning Claude. Don't push.
- `test/api.test.js` must keep passing.

## Review Focus

- **npm rendering:** npm strips some HTML. The gallery layout must still read as cards on npmjs.com. Task 2 checks the README with an npm-like renderer.
- **A stale media file after a code change:** `make.mjs` must be deterministic. Running it twice gives byte-identical files, except the timings in `results.json`. Task 1 tests this.
- **Snippet drift:** a gallery snippet that no longer runs against `dist/`. Task 2's snippet test catches it.
- **Dark mode on GitHub:** swatch strips and captions drawn on a transparent background can vanish. The media use opaque backgrounds. Task 1 checks that every image's alpha is 255.
- **A broken link after the paragraphs move:** links from `docs/` or the CHANGELOG to README anchors that no longer exist. Task 2 runs `test/api.test.js`, which checks anchors.

### Task 1: Media script and media

**Files:**
- Create: `docs/media/make.mjs`, `docs/media/CREDITS.md`, `docs/media/results.json`, `docs/media/*.gif|*.png`
- Test: `test/media.test.js`

**Interfaces:**
- Produces:
  - `node docs/media/make.mjs [--only <name>]` writes these files in `docs/media/`: `hero.gif`, `nesting.png` (or `.gif`), `pixel-art.gif`, `eink.gif` or `.png`, `threads.png`, `indexed.gif`, `swatches.png` and `animation.gif`;
  - `results.json`: `{ machine, node, load: {before, after}, hero: {width, height, clusterMs, cutsMs, totalMs}, files: {<name>: bytes} }`.

- [ ] **Step 1:** Write `test/media.test.js`. It reads `docs/media/results.json` and the files, then asserts:
  - every file in the Interfaces list exists;
  - `hero.gif` ≤ 1,572,864 bytes;
  - the total ≤ 6,291,456 bytes;
  - the mean of the card files ≤ 716,800 bytes;
  - every PNG decoded with fast-png has alpha 255 everywhere;
  - `results.json` has the keys above.

  It skips with a clear message if `docs/media/results.json` is missing.
- [ ] **Step 2:** Run `npx vitest run test/media.test.js`. Expected: skipped (no media yet).
- [ ] **Step 3:** Implement `make.mjs`.
  - Decode the photos with sharp and resize them, crops about 320–480 px wide.
  - Cluster with `buildClustering` and cut with `getPalette(k)`.
  - Map with `quantizeWithPalette` or `quantizeToIndicesWithPalette`.
  - Write GIFs with gifenc from the library's own indexed output, so every GIF frame is the library's output.
  - Draw swatch bars as pixel rectangles on an opaque background; no text rendering is needed, because captions live in the README.
  - The nesting strip has two rows for k = 4…12. The first is MMCQ via `quantize`, in its returned order; the second is ours, in split order.
  - The hero uses frames k = 2…64, with the swatch bar under each.
  - Measure the hero N as defined in the Global Constraints.
  - Make it deterministic: fixed frame lists, and no `Date` in the image data.
- [ ] **Step 4:** Run `npm run build`, then `node docs/media/make.mjs`, then `npx vitest run test/media.test.js`. Expected: PASS. Run `make.mjs` again and check that `git status` shows only `results.json` timing changes. That means comparing the image files' bytes: `sha256sum docs/media/*.{gif,png}` before and after.
- [ ] **Step 5:** Write `docs/media/CREDITS.md`, then commit: `"README media: a script that makes the hero, nesting strip and gallery from the library"`.
- [ ] **Step 6 (controller):** Publish a preview page with the media, for the maintainer to react to, before Task 2.
